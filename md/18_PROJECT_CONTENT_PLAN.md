# PROJECT CONTENT PLAN & EXPERIENCE MAP

Projects must NOT be primitive placeholders. The object must communicate the project's character.

## PROJECT PRESENTATION MODEL

For every project, the presentation follows a strict spatial and interactive flow:

1. **APPROACH:** The visitor sees the physical artifact illuminated in an alcove.
2. **IDENTITY:** Engraved metal plaques on the pedestal display the project name and tech stack.
3. **GRAB/FOCUS:** Clicking the artifact triggers spring-physics, snapping the camera to a tight, cinematic framing of the artifact's screen/surface.
4. **LIVE DEMO / CONTEXT:** The artifact powers on, revealing the live URL or a high-fidelity rendering of the application.
5. **PROBLEM/SOLUTION:** Textual context is revealed physically (e.g., printed on a blueprint beneath the device, or etched into the desk).
6. **CTA:** A distinct physical button (e.g., a heavy steel toggle) to "LAUNCH FULLSCREEN" or "VIEW REPOSITORY".

## INDIVIDUAL PROJECT MAPS

### 1. GET UNZIP
- **PROJECT IDENTITY:** Developer tool / file utility.
- **PHYSICAL REPRESENTATION:** An industrial-looking workstation monitor embedded into a heavy steel drafting desk.
- **INTERACTION:** Hovering causes the monitor mount to gently sway. Clicking pulls the camera into the monitor bezel.
- **PROBLEM/SOLUTION:** Etched into the steel desk surface.
- **LIVE DEMO:** An iframe or WebGL texture rendering the live Netlify deployment.

### 2. MS Security
- **PROJECT IDENTITY:** Mobile application with a full backend.
- **PHYSICAL REPRESENTATION:** A high-fidelity mobile device (phone) suspended or mounted on a precision robotic arm.
- **INTERACTION:** The robotic arm tracks the user's scroll position slightly. Clicking pulls the camera into portrait orientation viewing the phone screen.
- **PROBLEM/SOLUTION:** Displayed on a glass pane suspended next to the arm.
- **CTA:** "DOWNLOAD APK" physical button.

### 3. Atlas UI
- **PROJECT IDENTITY:** UI framework / Design system.
- **PHYSICAL REPRESENTATION:** A multi-pane glass display stack, representing layers of UI components separating physically in 3D space.
- **INTERACTION:** Hovering causes the glass layers to expand (explode view). Clicking aligns the camera perfectly perpendicular to read the UI.
- **PROBLEM/SOLUTION:** Projected text floating between the glass layers.

### 4. This Portfolio
- **PROJECT IDENTITY:** Meta-project. The world itself.
- **PHYSICAL REPRESENTATION:** A tilted, lit drafting table covered in blueprints of the 3D world architecture.
- **INTERACTION:** Hovering illuminates a drafting lamp. Clicking zooms onto the blueprints.
- **PROBLEM/SOLUTION:** The blueprints themselves explain the "zero-build" vanilla JS constraint.

## Public vs. private information boundary
**Decided:** the family-responsibility story is private — never written or spoken to visitors in any form. It informs tone, symbolism, and mood only. What's public: identity, personality, work, thinking, skills, and the general story of being self-taught — the *theme* of resilience, without the specific circumstance behind it.
